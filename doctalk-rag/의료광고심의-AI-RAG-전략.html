2. 데이터 품질이 떨어지거나 제공이 어려운 경우의 전략

전략 A: 공개 데이터로 RAG 기반을 먼저 구축

협회 데이터 없이도 확보 가능한 공개 소스:

소스데이터확보 방법
법제처의료법, 시행령, 시행규칙 전문공개 API
보건복지부의료광고심의 세부기준 고시공개 문서
법원의료광고 관련 판례판례검색 시스템
국회의료광고 관련 입법 자료, 질의서의안정보시스템
심평원의료행위 분류, 요양기관 정보HIRA API
의료광고심의위원회공개된 심의 결과 공고웹 크롤링
이것만으로 가능한 수준 "이 표현이 법적으로 문제가 되는가?" 수준의 1차 판단은 공개 데이터만으로도 가능하다.

전략 B: 시스템 사용 과정에서 데이터를 생성 (Compound 학습)

닥톡의 Compound 학습 패턴과 동일한 원리:

[현재] 데이터가 없다 | v [1단계] AI가 공개 법령 기반으로 1차 스크리닝 제공 | v [2단계] 심의위원이 AI 판단을 검토하고 "승인/수정/반려" 결정 | v [3단계] 그 결정이 곧 "라벨링된 데이터"가 된다 <-- 데이터 생성 시작점 | v [4단계] 쌓인 데이터로 RAG 품질이 점점 좋아짐 | v [반복] 사용할수록 AI가 심의 기준을 더 정확히 학습
핵심 데이터를 "받는 것"이 아니라 "시스템 사용 과정에서 생성하는 것"으로 전환한다.

심의위원 워크플로우에 라벨링을 자연스럽게 녹이기

광고 접수 --> AI가 1차 분석 결과 제시 | |-- 위반 의심 표현 하이라이트 |-- 관련 법령 조항 제시 +-- 유사 사례 제시 (초기엔 없음 -> 점점 쌓임) | v 심의위원이 최종 판단 | |-- [승인] / [반려] / [수정요청] <-- 라벨 |-- 사유 입력 (드롭다운 + 자유입력) <-- 라벨의 근거 +-- AI 분석 피드백 (선택) <-- 품질 개선용
포인트 심의위원 입장에서는 "AI를 위해 라벨링하는 것"이 아니라 "원래 하던 심의 업무를 하는 것"이다. 추가 작업이 거의 없다.

협회에 제안할 때의 프레이밍

❌ 잘못된 접근

"과거 데이터를 주세요"

결과: 없다 / 못 준다 / 정리가 안 됐다

✔ 올바른 접근

"시스템을 쓰시면 자연스럽게 데이터가 쌓이고, 쓸수록 AI가 똑똑해집니다"

결과: 협회는 데이터 정리 부담 없이 시작 가능, 시간이 지날수록 고유 자산 축적

3. RAG 적용 영역 설계

3.1 핵심 적용 영역

영역 1: 의료광고 심의 판단 지원 가장 핵심

데이터: 의료법/고시/지침 + 과거 심의 사례 + 유권해석/판례

[심의위원] "시술 전후 사진을 사용한 광고인데, 허용되나요?" | v [RAG 검색] 의료법 제56조 + 의료광고심의 가이드라인 + 유사 판례 3건 | v [AI 답변] "의료법 제56조제2항제8호에 따라 치료효과를 보장하는 전후 사진은 금지. 단, OO 조건 하에 허용된 사례 있음 [출처1][출처2]"

영역 2: 의료광고 자동 사전 스크리닝

데이터: 금지 표현 목록, 허용/불허 경계선 사례집, KCPI

활용: 광고 원문 접수 시 AI가 자동으로 위반 가능성이 높은 표현을 1차 스크리닝하여 심의위원 업무 부담 경감

영역 3: 통합 민원 창구 챗봇

데이터: 심의 신청 절차 FAQ, 심의 기준 가이드라인, 과거 민원 응대 내역

활용: 의사/병원이 "이런 광고는 심의 통과 가능한가요?" 같은 질문에 규정+사례 기반 사전 안내

영역 4: 법령 변경 시 자동 업데이트 (Karpathy Wiki 패턴)

기존 방식

법령 변경 → 심의위원이 직접 새 기준 학습 → 시간 소요

Wiki 방식

법령 변경 → AI가 자동으로 심의 가이드 Wiki 업데이트 → 심의위원은 항상 최신 기준 참조 가능

3.2 RAG 아키텍처 — 의료광고심의 맞춤 설계

[광고 원문 접수] | v [1. 안전 검사] 개인정보 포함 여부 확인 --> 포함 시 마스킹 | v [2. 자동 스크리닝] 금지 표현 DB 기반 1차 위반 탐지 | --> 명확한 위반: 즉시 플래그 | --> 경계선: 심의위원 판단 필요 표시 v [3. RAG 검색] 관련 법령 + 유사 심의 사례 + 판례 검색 | --> 검색 우선순위: ① 심의 사례 ② 법령/고시 ③ 판례 ④ 유권해석 | --> 3단계 깔때기: 50개 후보 --> 12개 재정렬 --> 6~8개 최종 v [4. AI 분석 보고서 생성] | --> 위반 의심 항목 + 근거 법령 + 유사 사례 제시 | --> 출처 표시: [법령1], [사례2] 형태 v [5. 심의위원 검토 & 결정] | --> 승인 / 반려 / 수정요청 + 사유 v [6. 학습] 결정 결과를 데이터로 저장 --> 다음 심의 시 RAG 품질 향상

3.3 검색 우선순위 설계

순위데이터 소스가중치이유
1순위과거 심의 결정 사례40%가장 실질적인 판단 근거 (같은 맥락의 선례)
2순위법령/고시/지침30%법적 기준선
3순위판례/유권해석20%경계선 케이스의 판단 근거
4순위금지 표현 목록10%명확한 위반 탐지용

3.4 안전 장치 설계

검사 항목대응이유
AI가 "이 광고는 합법입니다" 단정"위반 가능성이 낮습니다"로 표현 변경최종 판단은 반드시 심의위원이 해야 함
개인정보(병원명, 의사명) 노출마스킹 처리심의 과정의 공정성 보호
근거 없는 답변"관련 사례를 찾지 못했습니다. 심의위원의 직접 판단이 필요합니다"환각 방지
출처 미표시모든 판단에 [출처] 필수 첨부심의 근거의 투명성

5. 핵심 요약

데이터가 충분할 때

RAG = 과거 심의 사례 + 법령을 검색해서 심의위원에게 판단 근거를 제시하는 기술.
가장 중요한 데이터는 "과거 심의 결정 (광고 원문 + 결과 + 사유)" 이다.

데이터가 부족할 때

공개 법령으로 시작하고, 시스템 사용 과정에서 데이터를 생성한다.
심의위원의 일상 업무 자체가 라벨링이 되는 구조를 설계한다.
"데이터를 받는 것"이 아니라 "데이터가 만들어지는 시스템을 구축하는 것"이 핵심 제안 가치이다.
